## 启动

在项目根目录打开PowerShell，执行：

```powershell
.\start.ps1
```

首次会建立后端虚拟环境，按`backend/requirements.lock.txt`安装依赖、按`package-lock.json`安装前端依赖，再构建完整应用。需要可用的Python、Node.js/npm及首次安装时的网络；不会复制或覆盖`.env`、`.env.local`，不会导入或重置演示数据。已有依赖会检查，前端每次重新构建。

打开 <http://127.0.0.1:8000>，首次注册自己的账号。一个后端进程同时提供页面与`/api`；刷新`/materials`、`/analysis`等地址可继续使用。Ctrl+C停止服务，数据保留。默认仅监听本机。

| 命令 | 用途 |
| --- | --- |
| `.\start.ps1 -PrepareOnly` | 安装依赖并构建、检查，不启动，不创建数据库或会话密钥 |
| `.\start.ps1 -Check` | 只检查已有运行配置和构建，不安装、不改配置、不创建数据 |
| `.\start.ps1 -Port 8010` | 在指定本机端口启动 |
| `.\start.ps1 -Setup` | 重新校准后端依赖，并用npm ci重装前端依赖 |

已准备好构建及Python环境时，可从任意目录直接运行`backend/.venv/Scripts/python.exe -X utf8 backend/run.py`，无需再运行Vite。macOS/Linux可用`.venv/bin/python`手动安装锁定依赖，并在frontend执行`npm ci && npm run build:app`；Ubuntu/Python3.12/MySQL8.0.46的核心HTTP流程、数据迁移与恢复已在本轮实测，桌面浏览器等完整部署验收边界见[修复验收](修复验收_2026-11-01.md)。

## 构建与开发

| 构建 | 输出 | 访问接口 |
| --- | --- | --- |
| `npm run build` | `frontend/dist`，路径`/fmzh/` | 保留Pages静态演示；发布时显式VITE_USE_MOCK=true |
| `npm run build:app` | `frontend/dist-app`，路径`/` | 固定使用同源`/api`与真实后端，不受本地前端预览开关或旧API地址影响 |

完整应用构建附带`app-build.json`模式标记，后端拒绝把Pages产物当作完整应用。缺失JS资源和未知API返回404，不把首页HTML伪装成接口响应；构建目录以外的文件不公开。

在frontend执行`npm run preview`会按`/fmzh/`路径预览Pages产物，避免把静态资源误回退成HTML。静态模式只提供明确的免登录预览入口，注册和真实账号登录在完整应用中使用。

独立开发前端时，后端用`python -X utf8 run.py --api-only --dev`，前端另起`npm run dev`并设置`VITE_USE_MOCK=false`。默认允许本机5173来源，其他独立前端来源可通过进程环境`FMZH_CORS_ORIGINS`用逗号明确指定；完整应用同源访问不需要另开跨域。

## 本地接入真实大模型

本地模拟流程已就绪后，在本机编辑 `backend/.env`，不要将Key写进前端、文档或Git。该文件已被Git忽略，启动脚本不会覆盖它。填写实际平台的以下四项，然后重启后端：

```dotenv
LLM_MOCK=false
DEEPSEEK_API_KEY=在本机填写实际Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

上面地址和模型是当前默认值；使用其他OpenAI兼容平台时，按该平台填写地址前缀和模型名。后端自动在地址后追加 `/chat/completions`，不要把这个完整路径再填入地址。历史 `DEEPSEEK_*` 配置名继续保留，使用其他兼容平台无需改代码。Key无需发到聊天里；只需说明配置已填，以及所用接口地址和模型名，即可继续检查真实调用与生成结果。真实模型连通性和效果在实际调用通过前仍为待验收。

2026-11-02官方平台的V4.1 Flash使用 `DEEPSEEK_MODEL=deepseek-flash`。常规测试保持Mock或本机假上游，构建和Git同步不需要消耗付费Token；真实模型只做必要的少量联调。

## 数据与重启

- SQLite相对路径始终以backend目录为基准，上传目录也不受启动时工作目录影响；设置的绝对路径保持有效。启动前检查目录和构建，按需创建缺失数据目录；已有库仍走增量建表/迁移。
- 默认数据库是`backend/fmzh.db`，上传是`backend/uploads/`。未自定义会话密钥时，首次启动在数据库同级的`.runtime/session.key`生成持久化密钥；重启复用。已有自定义SECRET_KEY原样使用。
- 备份与迁移应一起保留数据库、上传目录、`.runtime/session.key`及私有环境配置。停止服务后复制，恢复到同一组数据；缺失或损坏的密钥不会被静默覆盖。上述文件不提交Git。
- 普通页面刷新和后端重启均不清空账号、任务、分析或上传。专注运行中的不足一分钟和未提交草稿仍遵循已有交互规则。
