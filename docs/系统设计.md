# 《期末周别慌！》系统设计文档

> 对应需求文档：`简要用户需求列表.doc`（FMZH-USR-0001 ~ 0067，本文档覆盖 MVP 范围，其余为扩展方向）

## 1. 系统目标

面向大学生期末复习的一站式网站：用户上传复习资料、用自然语言描述学习状态，系统调用大模型生成**个性化**的知识点权重、常考点、复习计划和自测题，并以每日任务打卡的形式落地执行。

核心设计原则（来自项目介绍文档）：

1. **资料来源**：只基于用户上传的资料（历年题、老师重点、PPT、笔记、作业等），不做联网搜索；
2. **输入结构化**：自然语言先转成固定 JSON 用户画像；
3. **输出固定格式**：提示词 + JSON 模式双重约束大模型输出。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  浏览器（Vue 3 SPA）                                      │
│  登录/首页/考试/资料/画像表单/分析结果/任务打卡             │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP + JSON（Axios，JWT 认证）
┌──────────────────────▼──────────────────────────────────┐
│  FastAPI 后端（单进程即可）                                │
│  routers/  ← 路由 + 鉴权 + 参数校验（Pydantic）            │
│  services/ ← 业务逻辑：文件解析、LLM 调用、计划落库         │
│  models/   ← SQLAlchemy 模型                              │
└──────────┬───────────────────────┬──────────────────────┘
           │                       │
      ┌────▼────┐             ┌────▼─────────────────┐
      │ SQLite  │             │ 大模型 API（外部）    │
      │ fmzh.db │             │ Key 只存在后端 .env   │
      └─────────┘             └──────────────────────┘
  uploads/ 目录（本地磁盘存上传文件，解析出的纯文本入库）
```

### 2.1 分层说明

| 层 | 职责 |
|---|---|
| routers | 路由、鉴权（`get_current_user` 依赖）、参数校验（Pydantic schema），不含业务细节 |
| services | `llm_client`（大模型封装）、`prompts`（提示词 + Mock）、`file_parser`（TXT/PDF/DOCX 解析）、`plan_service`（计划→任务落库） |
| models | 个人业务表按 `user_id` 隔离；courses 为管理员维护的全站公共科目 |

### 2.2 关键设计决策

| 决策 | 内容 | 理由 |
|---|---|---|
| LLM Mock 模式 | `LLM_MOCK=true` 时走内置启发式提取器/示例数据 | 无 API Key、无网络也能完整演示；Mock 画像提取器故意漏字段，补全流程可真实演示 |
| 两次 LLM 调用 | ①自然语言→画像 JSON；②画像+资料文本→分析 JSON | 画像可补全、可复用；分析输入受控 |
| Token 控制 | 单份资料截 6000 字、总计 30000 字 | 避免超出上下文，MVP 不做向量库 |
| 输出强校验 | 提示词内嵌 JSON Schema + `response_format=json_object` + Pydantic 校验失败自动重试一次 | 保证落库数据格式稳定 |
| 计划落库 | AI 计划的 review_plan 自动生成 tasks 表记录（source=ai），重新生成时保留完成记录及固定时段，仅替换未完成且未定时任务 | 打卡/统计是纯数据库操作，不依赖大模型；手动确定的时段不被自动改期 |
| 数据隔离 | 所有查询强制 `user_id` 过滤 | 需求 FMZH-USR-0066：只能访问自己的数据 |
| 安全 | bcrypt 密码哈希、JWT（7 天）、上传限格式限大小（20MB） | 基本安全底线 |

## 3. 数据库设计（当前 22 张表）

```
users ──< exams ──< materials
  │         │
  │         └──< user_profiles ──< analyses
  │                                 │
  └────────────< tasks ─────────────┘   （tasks 由 AI 计划生成或手动添加）
```

| 表 | 关键字段 | 说明 |
|---|---|---|
| users | username(唯一), hashed_password, auth_key, nickname, student_no, major, grade | 账号体系；auth_key 绑定不可继承的会话身份 |
| exams | user_id, subject, exam_date, location, duration_minutes, note | 考试安排，倒计时依据 |
| materials | user_id, exam_id, title, source_type, file_path, file_type, text_content, text_locations, parse_status, description, tags, weight | 文件、解析文本及真实位置索引；source_type 支持七类需求来源及其他 |
| user_profiles | user_id, exam_id, raw_text, target, target_band, learning_status, available_days, daily_hours, weak_chapters(JSON), output_need(JSON), is_complete, missing_fields(JSON) | 第一次 LLM 调用产物；一科一份，补全时覆盖更新 |
| analyses | user_id, exam_id, profile_id, result_json, status, error_msg | 第二次 LLM 调用产物，result_json 为固定格式 |
| tasks | user_id, exam_id, analysis_id, title, plan_date, start_time, end_time, estimated_minutes, location, difficulty, detail, repeat_rule, repeat_until, repeat_group_id, priority, sort_order, is_done, done_at, source | source=ai/manual；可选同日时段，固定时段按实际分钟；重复展开为独立任务，共享组 ID |
| collections | user_id, item_type, material_id, title, content, question_key | 收藏与错题本；用户+题干去重键唯一 |
| mood_records | user_id, record_date, mood_score, note | 情绪记录 |
| daily_pressure_records | user_id, record_date, score, breakdown(JSON), computed_at(UTC), source, formula_version | 每日压力快照；账号+北京时间日期唯一，保存当时分数及分项；注销清理，历史不随任务变化重写 |
| courses | name, code, teacher, credit, term | 全站公共课程，管理员维护 |
| focus_sessions | user_id, exam_id, subject_snapshot, start_time, end_time, duration_minutes | 实际专注记录；考试删除后保留科目快照及分钟数 |
| focus_goals | user_id, goal_date, target_minutes | 每日专注目标 |
| study_settings | user_id, daily_minutes | 全科共享时间预算 |
| notification_preferences | user_id, enabled, exam_enabled, task_enabled | 站内通知开关 |
| reminders | user_id, target_type, target_id, target_created_at, event_time, advance_minutes | 事项提醒设置 |
| notifications | user_id, target_type, target_id, target_created_at, is_read, deleted_at | 到期通知与历史 |
| quiz_attempts | id, user_id, exam_id, analysis_id, subject, questions_json, answers_json, result_json, status | 服务端题目快照、答卷及判分历史 |
| qa_conversations | id, user_id, exam_id, title, created_at, updated_at | 按账号和科目隔离的资料问答会话 |
| qa_messages | conversation_id, role, content, created_at | 会话消息历史，注销时随会话清理 |
| file_cleanup_jobs | id, file_path, attempts, last_error, created_at | 业务删除提交后处理文件，失败可由管理员重试，处理前重验共享引用 |
| ics_import_receipts | id, user_id, exam_id, imported, created_at | 确认导入时同事务保存的幂等凭据；预览不写库 |
| operation_logs | actor_id, actor_name, action, target_id, method, path, status_code, created_at | 操作者快照与动作/结果，不存正文、密码、令牌及查询参数 |

统计页聚合任务与专注记录；知识点掌握状态按最近一次覆盖该知识点的已交卷自测计算，≥80% 标记已掌握，其余已测标记薄弱，无记录为未测，附判分依据并隔离用户/科目。资料默认权重与手动调整同时支持；来源识别仅作建议，问答只使用本科解析成功资料。

考试删除同事务清理任务、画像、分析、自测、问答及提醒，资料转未分类；专注解绑考试并保留科目快照，在统计/周报中作为历史时长展示。学生和管理员资料删除共用服务，先提交数据库删除和文件清理凭据，再安全清理无共享引用的上传文件。

任务采用可选同日北京时间起止时刻，地点、难度与复习内容随任务保存；未指定时段的旧任务保留原日期、时长及打卡。每天、周一至周五、每周规则需填写有限截止日，不晚于考试日；一次最多 180 项、日期跨度最多 365 天。预览只读并按全科预算提示，确认批量保存同一事务，每个日期独立打卡/编辑；改期或换科目成为单次例外。组删除仅从选中日期起清理未完成项及提醒，保留完成记录、较早日期和独立例外。

自动排程、反馈重排、AI/倒推重建及减负保留固定时段；容量不足或固定时段逾期时提示人工取舍。快照包含时段与全部新字段，防止编辑后套用旧预览。真正半天减负已实现上午/下午选择，口径见 README。

全科排程确认与任务/打卡、预算、考试增删改、倒推、AI任务替换及既有ICS/反馈/减负提交共用账号写锁。先锁定再刷新ORM缓存、重验最新快照，直到整体提交或回滚才释放；预算与当日目标同事务保存。模型调用前短事务复制规划输入并释放锁，返回后重验输入及会话，变化返回409/401；分析及任务原子保存，容量冲突仅保留分析及原任务。既有SQLite真实并发与提交失败回滚回归覆盖，不新增表列或改动成绩分档。

日历组件在既有科目页面中提供日/周/月、日期导航及独立科目筛选，周视图为周一至周日。未定时任务与只有日期的考试置于上方，固定任务按真实时刻显示在24小时时间轴；存量重叠采用分栏展示，不篡改时段。纵向拖动按15分钟定位并扣除抓取偏移，纯横向跨日保留原时刻；点击任务可精确输入日期或时刻，窄屏周/月表格在内部横向滚动。

日历移动通过专用预览/保存接口。每项任务响应附带由任务状态及创建时间计算的 move_fingerprint，无新增表列；预览只读，保存先取账号写锁，再校验原任务快照、完成状态、时长、考试截止日、跨科时段及预算，成功后才在界面更新。结束时间由原分钟数推导，不能借移动修改时长；清空时段仍保留分钟和复习内容。超预算需显式确认，时段冲突无法覆盖；改期仅让该重复实例脱离组，同日改时段仍属于原组。完成任务不允许日历移动。网络结果不明时重新读取服务端日程；其他页面已修改时拒绝覆盖。现有提醒继续以用户独立确认的基准时刻计算，不随任务改时段自动覆盖提醒。

时段检测采用同日左闭右开区间交集，首尾相接允许；同账号所有科目及已完成任务均占用真实时段，未定时任务不推测起止。重复任务逐日检测，ICS 同时检测与现有任务及文件内部的交集。预览只读，创建和改期在账号写锁内重新查询并校验，冲突返回 409 且整批回滚；同账号跨科并发写入不能各自通过过期预检。存量重叠通过查询与课程页显示，允许保留原时段仅改文字/科目；任何时段变化重新校验。全科排程也提示今日及以后已有固定时段重叠。日预算超额独立提示，手动安排仍可确认保留。

ICS 预览签名有效期 10 分钟，绑定用户会话和全科日程快照，不写库；确认先取写锁，再重验快照、预算与截止日，任务和幂等凭据同事务保存。当前仅接收单次事件，RRULE 重复规则明确拒绝；导入按上海日期处理，同名但时段/地点/内容不同的事件保留，全天事件作为 60 分钟未定时任务。固定任务导出真实 UTC 起止、地点和内容，未定时任务显式标记 08:00 占位；本系统回导仍识别为未定时。跨午夜和非整分钟时段明确拒绝，不静默丢失时间；旧导入凭据继续防重复。

操作日志由中间件按路由白名单记录动作与响应状态，管理员可分页筛选；账号注销后保留快照。审计持久化异常写入服务端日志，不将已经成功提交的业务伪装成失败。

账号访问令牌携带 typ=access 与当前 auth_key，找回令牌携带 typ=reset；改密、重置和退出轮换会话键，旧凭证失效。注销按关联顺序清理全部个人业务数据，保留其他账号仍引用的文件；新注册跳过历史残留 ID。

自测在开始时固定服务端题目与答案快照，公开响应隐藏答案；提交时按题型确定性判分，判分结果与错题自动入本同事务保存。并发提交通过答卷状态条件更新及错题唯一索引去重。

已有数据库在启动时通过 services/schema_upgrade.py 补列、填充独立会话键和补建去重索引，保留原数据，无需删库。本轮仅为 tasks 增加 8 列及重复组索引，总表数仍为 21；旧任务默认未定时、单次、适中难度、空地点及内容。

资料的 text_locations 保存解析文本偏移与 PDF 页、Word 段落/表格行、TXT 行的真实对应关系；旧资料缺少页码时只显示解析文本位置。分析中的 citations 保存经服务器核对的资料 ID、创建时间、原文位置和正文 SHA256。查询引用按用户/科目/分析隔离，资料修改、删除、移科目或 ID 复用会使旧引用失效。模型未提供有效引文时仅做保守关键词定位并明确提示，找不到则不展示出处；片段匹配不作为必考或频次已核实的证明。

动态调整沿用全科排程器：保留手动与完成记录，按最近自测及打卡调整原始权重，向低分知识点追加 30 分钟专项练习，同批反馈不重复追加。预览无写入，确认核对任务/预算/考试/分析/自测快照；容量不足或考试过期拒绝应用，权重与全部任务变更同事务保存。

目标选择保留川大 10 档分数区间和绩点，并映射到需求中的保及格、稳中等、冲高分三类策略。旧库在统一迁移入口补 target_band、materials.weight 并按来源回填，保留已有手动权重。

## 4. AI 输出契约

### 4.1 用户画像（第一次调用）

```json
{
  "target": "pass",              // pass|medium|high，缺失为 null
  "learning_status": "weak",     // weak|medium|good，缺失为 null
  "available_days": 5,           // 缺失为 null
  "daily_hours": 3,              // 缺失为 null
  "weak_chapters": ["极限", "积分"],
  "output_need": ["知识点权重", "复习计划", "自测题"]
}
```

四个必填字段（target/learning_status/available_days/daily_hours）任一为 null → `is_complete=false` 并返回 `missing_fields`，前端展示补全表单，补全内容以"补充说明"追加到 raw_text 后重新提取。

### 4.2 复习分析（第二次调用）

以下是大模型输出及服务端保存的内部结构。公开分析响应会隐藏 quiz 的答案、解析及等价写法，交卷后通过自测判分接口返回。

```json
{
  "course": "高等数学",
  "summary": "总体策略总评",
  "knowledge_points": [
    {"name": "极限与连续", "weight": 0.9, "importance": "high",
     "recommend_reason": "历年题高频", "source": "历年题", "suggest_hours": 6}
  ],
  "exam_focus": [
    {"content": "洛必达法则求极限", "level": "must", "basis": "近3年每年必考", "source": "历年题"}
  ],
  "review_plan": [
    {"day": 1, "date": "2026-09-08", "title": "极限与连续",
     "estimated_minutes": 180, "priority": 1, "detail": "看笔记+刷历年题1-3"}
  ],
  "quiz": [
    {"question": "…", "options": ["A. …", "B. …"], "answer": "B",
     "analysis": "解析", "knowledge_point": "极限"}
  ]
}
```

提示词约束资料来源与目标；`services/recommendation_strategy.py` 在模型输出后执行确定性校验，真实模型与后端 Mock 共用。既有十档分数和绩点规则保持不变，只按目标、基础、薄弱章节与剩余天数调整练习比例。同日累计时长不超过本科份额；超额内容记录为未安排并提示，不增加全科预算。

新保存的分析 JSON 增加 `strategy`（目标、生成时容量、当前计划分钟、未安排分钟、三类练习比例/分钟及说明）；知识点增加精确 `suggest_minutes` 和 `practice_hint`，保留小数 `suggest_hours`。每项计划增加 `activities`，各活动分钟合计等于任务时长；知识点分配也是同一计划时间的展示，不能重复计量。反馈重排同时更新这些分钟，引用中的日期按JSON格式保存。旧分析缺少 strategy 时返回null。完整字段见接口文档4.11。

## 6. 扩展方向（非 MVP）

错题本、合并导出、日/周/月历与 ICS、番茄钟、资料问答、思维导图、提醒、周报、原文依据和管理员后台已有实现。历史学习时段推荐、真正半天减负、重要操作确认及每日压力自动计算已补齐。压力实时值与每日快照复用同一公式；后端生命周期内每分钟检查，北京时间00:05后保存、启动补当天，唯一约束和账号锁避免重复，单账号失败独立重试，停机历史不伪造。功能清单59项已打通，通用排程并发一致性已收尾；运行配置、真实大模型调用路径与整体验收仍待完成，API配置保留待填，公网后端未部署。PPT/图片解析为扩展方向；具体完成度以 README 功能表为准。优化推荐内容时保持现有分数区间与绩点映射不变。
