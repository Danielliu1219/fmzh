# 《期末周别慌！》API 接口文档

- 统一前缀：`/api`（开发时前端通过 Vite 代理 `http://127.0.0.1:8000`）
- 认证方式：除注册、登录、密码找回两步外，请求头需带 `Authorization: Bearer <access_token>`；找回令牌不能用于登录态接口。
- 交互式文档：后端启动后访问 http://127.0.0.1:8000/docs
- 错误格式：`{"detail": "错误描述"}`，常见状态码 400（参数/业务错误）、401（未登录）、404（不存在）、409（账号已存在）、502（AI 调用失败）

---

## 一、认证 `/api/auth`

### 注册（成功即自动登录）
`POST /api/auth/register`
```json
{"username": "testuser", "password": "test123456", "nickname": "小明", "student_no": "", "major": "", "grade": ""}
```
响应 `200`：
```json
{"access_token": "eyJ...", "token_type": "bearer", "user": {"id": 1, "username": "testuser", "nickname": "小明", "student_no": "", "major": "", "grade": "", "created_at": "..."}}
```
约束：username 3-20 位字母数字下划线（唯一，重复返回 409）；password 6-32 位。

### 登录
`POST /api/auth/login`，body `{"username": "...", "password": "..."}`，响应同上；账号或密码错误返回 401。

**账号锁定（1.2/1.3）**：同一账号连续 3 次密码错误即锁定 30 分钟，锁定期内即使密码正确也返回 403（detail 含剩余解锁时间）；30 分钟后自动解锁；登录成功清零失败计数。401 提示会显示「连续错误 x/3 次」，锁定时返回 403。

### 获取当前用户 / 修改资料
```
GET  /api/auth/me
PUT  /api/auth/me    body: {"nickname": "新昵称", "major": "..."}（字段均可选，另支持 student_no / grade / class_name 班级 / avatar 头像色值）
```

### 修改密码（1.5，需登录）
`POST /api/auth/change-password`
```json
{"old_password": "原密码", "new_password": "新密码(6-32位)"}
```
响应 `200` 返回最新用户信息；原密码错误返回 400「原密码不正确」，新旧相同返回 400。成功后清除锁定状态并撤销此前的全部登录/找回凭证，前端回登录页。

### 密码找回（1.4，无需登录，两步）
```
POST /api/auth/reset-password/verify   body: {"username": "账号", "student_no": "学号"}
POST /api/auth/reset-password/confirm  body: {"reset_token": "...", "new_password": "新密码(6-32位)"}
```
verify：账号与学号匹配则返回 `{"reset_token": "...", "nickname": "...", "locked": true/false, "message": "..."}`（令牌 10 分钟有效）；不匹配返回 400「账号与学号不匹配」。
confirm：重置密码成功并**立即解锁账号**，返回 `{"ok": true, "message": "密码重置成功，账号已解锁..."}`。

找回令牌绑定该账号当前会话身份；成功重置后，原登录及找回令牌均失效，重复使用返回 400。登录令牌不能调用找回确认，旧格式令牌、过期令牌和账号重建前的令牌均不能访问登录态接口。

### 退出登录（需登录）
`POST /api/auth/logout`，响应 `{"ok": true}`。撤销该账号此前的全部登录/找回凭证；前端清除当前会话与未提交的自测草稿。

### 注销账号（1.7，需登录）
`DELETE /api/auth/me`
二次确认由前端完成；后端清理考试、任务、资料、画像、分析、专注、情绪、收藏、预算、提醒通知与自测答卷，删除用户记录及上传文件。仍被其他账号引用的共享文件保留；文件路径越出上传目录时返回 409 并拒绝操作。响应 `{"ok": true, "message": "账号已注销，个人数据已清理"}`。新注册账号跳过遗留业务数据中的用户 ID，旧令牌即使遇到 ID 重用也失效。

## 二、考试 `/api/exams`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/exams` | 我的考试列表（按考试日期升序）；支持 query 参数 `subject`（模糊）、`date_from`/`date_to`（考试日期区间，2.4） |
| POST | `/api/exams` | 录入考试 |
| PUT | `/api/exams/{id}` | 修改（字段均可选，另支持 `color` 科目颜色标签） |
| DELETE | `/api/exams/{id}` | 原子清理任务/分析/自测/问答/提醒；资料转未分类，专注保留科目快照 |
| POST | `/api/exams/{id}/generate-schedule` | 倒推生成备考时间表（2.7） |
| POST | `/api/exams/import-ics` | ICS 预览，不写库（multipart/form-data） |
| POST | `/api/exams/import-ics/confirm` | 确认预览并幂等保存任务 |
| GET | `/api/exams/export-ics` | 导出考试+任务为 ICS 日历文件（2.13） |

创建 body：
```json
{"subject": "高等数学", "exam_date": "2026-09-12", "location": "教三101", "duration_minutes": 120, "note": "闭卷", "color": ""}
```

**倒推生成备考时间表（2.7）**：`POST /api/exams/{id}/generate-schedule`，body `{"daily_minutes": 180, "start_date": "可选"}`。从开始日到考试前一天每天生成不超过 daily_minutes 的复习任务（source=ai，越临近考试优先级越高，重复生成会替换旧的【倒推】任务）。响应：
```json
{"created": 5, "total_minutes": 900, "start_date": "2026-10-15", "end_date": "2026-10-19", "conflicts": [{"date": "...", "existing_minutes": 300, "planned_minutes": 480, "limit_minutes": 480}]}
```
`conflicts` 非空表示这些日期与现有日程冲突（当天总时长超上限），需用户手动调整；考试日期早于等于今天返回 400。

**ICS 导入预览（2.12）**：`POST /api/exams/import-ics`，multipart 字段 `file`（.ics，≤20MB）、`exam_id`；可选 `daily_limit_minutes` 只能收紧全科预算。最多 500 个单次事件，重复规则须先展开；事件日期必须在今天至考前，未解析到有效事件返回 400。预览不写任何表，取消没有副作用。响应示例：
```json
{"imported":0,"count":1,"skipped":0,"already_imported":false,"events":[{"title":"复习","day":"2026-11-01","minutes":60}],"daily_limit_minutes":240,"conflicts":[],"preview_token":"签名预览凭据","note":"按上海日期合并；全天事件按60分钟导入"}
```
有冲突时列出日期、原因、现有及计划分钟数，不能确认。预览凭据有效期 10 分钟，绑定当前账号会话、考试及全科任务/预算快照。

**确认导入**：`POST /api/exams/import-ics/confirm`，body `{"preview_token":"预览返回值"}`。写锁内重验快照和约束，任务与幂等凭据同事务保存。返回 `{"imported":1,"skipped":0,"conflicts":[],"already_imported":false}`；重复确认返回 `already_imported=true`，不新增任务。修改任务、预算、考试、切换会话或凭据过期返回 409，需重新预览。

**ICS 导出（2.13）**：`GET /api/exams/export-ics`，返回 `text/calendar` 文件，采用标准 TEXT 转义、75 字节 UTF-8 折行、UTC 时间及全天事件非包含结束日期。当前任务仅有日期，08:00 为日历展示占位；文件名 `fmzh_YYYYMMDD.ics`。

## 三、复习资料 `/api/materials`

### 上传（multipart/form-data）
`POST /api/materials`
| 字段 | 说明 |
|---|---|
| file | 文件（.txt / .pdf / .docx，≤20MB） |
| title | 标题（必填） |
| exam_id | 所属科目（可选） |
| source_type | 历年题 / 老师重点 / 平时作业 / 课堂笔记 / 教材章节 / 实验报告 / 练习题 / 其他（默认"其他"） |
| description | 说明（可选） |
| tags | 标签（可选） |

上传前经**统一校验**（公共功能 · 用例 9.5）：扩展名白名单 → 大小 ≤20MB → **后缀与内容头安全扫描**
（内容与扩展名不符的伪装文件、含二进制内容的“纯文本”都会被拒绝，返回 `400` 并说明原因）。

上传后自动解析正文存入数据库；解析失败资料仍保存，`parse_status` 为 `failed`（不阻断上传）。

**资料权重（用例 4.2）**：`weight` 无需上传时填写，后端按 `source_type` 自动给默认值
（老师重点 1.00 / 历年题·练习题 0.85 / 平时作业·课堂笔记 0.70 / 教材章节·实验报告 0.55 / 其他 0.50），
学生随后可在编辑接口中手动调整。资料响应同时带 `default_weight`（当前来源的默认值），供前端「恢复默认」。

### 列表（全文搜索 + 筛选 + 排序）
`GET /api/materials?exam_id=1&keyword=洛必达&source_type=历年题&tag=重点&date_from=2026-10-01&date_to=2026-10-14&sort=date_desc`（参数均可选）

| 参数 | 说明 |
|---|---|
| exam_id | 按科目筛选 |
| source_type | 按来源类型筛选 |
| tag | 按标签筛选（模糊匹配） |
| keyword | **全文搜索**：匹配标题、说明、标签和**解析出的正文**；命中时响应带 `snippet`（命中片段） |
| date_from / date_to | 按上传日期区间筛选（`YYYY-MM-DD`） |
| sort | `date_desc`（默认，新→旧）/ `date_asc` / `title` / `source_type` / `exam` |

每条资料均返回 `weight`（当前资料权重 0~1）、`default_weight`（按来源类型的默认权重）与 `weight_level`（权重档位：高 / 中 / 低）。

### 来源辅助识别建议（用例 3.2）
`POST /api/materials/source-suggestion`（multipart/form-data，字段 `file`）

上传前传入同一文件，后端按**文件名 + 解析正文**匹配七类来源特征，返回：
```json
{ "source_type": "课堂笔记", "confidence": "high", "reason": "文件名含「笔记」；正文出现「课堂」3 次" }
```
`confidence` 为 `high` / `medium` / `low`；没有明显特征时 `source_type` 为「其他」。建议仅作参考，学生可改选。

### 详情 / 编辑 / 删除
```
GET    /api/materials/{id}    响应含 text_preview（解析文本前 1000 字）
PUT    /api/materials/{id}    编辑资料 / 移动分类（用例 3.3）
DELETE /api/materials/{id}    同时删除磁盘文件
```

`PUT /api/materials/{id}` 请求体（JSON，字段**全部可选**，只更新请求里出现的字段）：
| 字段 | 说明 |
|---|---|
| title | 标题（不可为空白） |
| exam_id | 所属科目；传 `null` 表示移出科目（回到「未归类」） |
| source_type | 来源类型（同上表白名单）；改了来源且未传 `weight` 时，权重回到新来源的默认值 |
| description | 说明 |
| tags | 标签 |
| weight | 资料权重 0~1（用例 4.2，手动调整）；传 `null` 不处理 |

### 合并导出复习笔记（用例 3.6）
`POST /api/materials/merge`

| 字段 | 说明 |
|---|---|
| material_ids | 勾选的资料 id 数组（必填，至少 1 个；自动去重并保持传入顺序） |
| title | 笔记标题（选填，默认「复习笔记」） |

返回：
```json
{ "title": "复习笔记", "markdown": "# 复习笔记\n...", "material_count": 3, "total_chars": 8421, "warnings": [] }
```
`markdown` 为合并后的笔记正文（每份资料一节，含来源类型 / 科目 / 标签等元信息）；
**导出格式由前端决定**（Markdown 文件下载 / 浏览器打印为 PDF）。`warnings` 列出没有正文或正文被截断的资料。

## 四、收藏与错题本 `/api/collections`

收藏的资料、收藏的题目、自测答错的题目共用一个本子，用 `item_type` 区分。

### 列表
`GET /api/collections?item_type=material&source=quiz`（参数均可选）

| 参数 | 说明 |
|---|---|
| item_type | `material`（资料）/ `question`（题目） |
| source | `manual`（学生手动收藏）/ `quiz`（自测答错自动入本） |

### 手动收藏
`POST /api/collections`

| 字段 | 说明 |
|---|---|
| item_type | `material` / `question`（必填） |
| material_id | 收藏资料时必填，须属于当前用户 |
| title | 收藏题目时的题干（必填）；收藏资料可不填，默认取资料标题 |
| content | 题目详情 JSON（选项 / 答案 / 解析 / 知识点，选填） |

同一份资料重复收藏时直接返回已有记录，不重复创建。

### 自测答错题批量入错题本（供用例 4.6 判分调用）
`POST /api/collections/mistakes`
```json
{ "mistakes": [ { "title": "题干", "content": "{\"answer\":\"B\"}", "knowledge_point": "极限" } ] }
```
同一用户下题干相同的题只记一次（不重复堆积）；返回本次新增的记录列表。

### 移除
`DELETE /api/collections/{id}` —— 收藏与错题通用

## 五、AI 分析 `/api/ai`（核心）

### 第一次调用：生成用户画像
`POST /api/ai/profile`
```json
{"exam_id": 1, "raw_text": "我这门课基本没学，只想及格，还有五天考试"}
```
响应 `200`：
```json
{
  "exam_id": 1,
  "raw_text": "我这门课基本没学，只想及格，还有五天考试",
  "target": "pass",
  "learning_status": "weak",
  "available_days": 5,
  "daily_hours": null,
  "weak_chapters": [],
  "output_need": ["知识点权重", "复习计划", "自测题"],
  "is_complete": false,
  "missing_fields": ["daily_hours"]
}
```

### 补全画像
`POST /api/ai/profile`（同一接口，supplement 会追加到已保存的描述后重新提取）
```json
{"exam_id": 1, "supplement": "每天能学3小时"}
```

### 分数区间目标与画像回读（2026-10-19）

`POST /api/ai/profile` 新增可选 `target_band`，响应同步返回该字段。前端通过可拖动的分数区间条选择；明确选择优先于自然语言中模糊的目标描述。旧 `target` 字段保留为内部推荐策略，旧客户端请求仍兼容。区间与绩点按[川大教务处公开对照表](https://jwc.scu.edu.cn/info/1066/3444.htm)：

| target_band | 分数区间 | 绩点 |
|---|---|---|
| D | 及格档（60 分及格线） | 1.0 |
| D+ | 61–62 | 1.3 |
| C- | 63–65 | 1.7 |
| C | 66–69 | 2.0 |
| C+ | 70–72 | 2.3 |
| B- | 73–75 | 2.7 |
| B | 76–79 | 3.0 |
| B+ | 80–84 | 3.3 |
| A- | 85–89 | 3.7 |
| A | 90–100 | 4.0 |

`GET /api/ai/profile/{exam_id}` 返回本科最新 `ProfileOut`（包含 `raw_text`、`target_band` 等字段），用于课程切换与重新编辑；无画像或访问他人考试返回 404。旧画像的 `target_band` 为 null；前端只为编辑提供初始档位，重新生成时才写入明确目标。补全请求保留已有目标区间；未传 `target_band` 的全新自然语言描述会清除旧区间，避免错误沿用。

后端启动时自动为已有画像表补列，不清空旧记录。分析上下文包含完整目标区间、对应绩点及用户补充描述；前端演示结果也展示所选区间。未选课程时前端展示公共输入界面，仅禁止提交，选择课程后按科目保存草稿并加载已有画像和方案。

### 第二次调用：生成复习分析
`POST /api/ai/analyze`
```json
{"exam_id": 1}
```
前置条件：画像已完整（否则 400）；该科目至少有一份解析成功的资料（否则 400）。
响应 `200` 的 `result` 字段为固定 JSON（详见 docs/系统设计.md §4.2）：`course`、`summary`、`knowledge_points`、`exam_focus`、`review_plan`、`quiz`。

**分级推荐（4.11）**：按画像目标 `pass` / `medium` / `high` 输出差异化策略。`summary` 以「【保及格策略】/【稳中等策略】/【冲高分策略】」开头；知识点按权重降序返回；保及格会把 `weight < 0.6` 的知识点降为 `low` 并压缩建议时长，冲高分提高高权重知识点的建议时长；`review_plan` 主题随档位不同，天数不超过 `available_days`、单日不超过 `daily_hours*60` 分钟。

**依据来源（4.13）**：每个知识点的 `recommend_reason` 与每条 `exam_focus.basis` 都以「依据来源：X」标注来源，X 为七类资料类型之一，缺来源时标为「所上传复习资料」。

**常考题型与高频考点（4.7）**：`question_types` 为题型分布数组，字段 `type` / `count` / `frequency`（0~1）/ `basis` / `source`，基于历年题与练习题等资料统计；`exam_focus[].frequency` 为该考点在资料中的出现次数/年份数，返回时按 `frequency` 降序排列。大模型未给出题型分布时，后端按考点描述中的「选择/填空/计算/证明/应用/简答/综合」关键词兜底推断，并在 `basis` 注明「根据分析中的考点描述推断」。

### 动态调整计划与权重（用例 4.12）
`POST /api/ai/analyses/{exam_id}/replan`

先预览：`{"apply": false}`；确认时发送 `{"apply": true, "fingerprint": "预览返回的标识"}`。

- 输入信号为本科 AI 任务完成情况、本科最近 20 次已交卷自测中每道题的最近一次作答、考试剩余天数；重复作答以最新结果为准。无答卷时仅兼容有明确 `exam_id` 的本科历史错题，未知科目错题不混入其他课程。
- 返回 `days_left`、`done_tasks`、`total_tasks`、`completion_rate`、`wrong_questions`、`weights[]`、本科 `plan[]`、全科 `scheduling`（`assignments` / `days` / `daily_minutes` / `conflicts`）、`fingerprint`、`applied`、整数 `task_count` 和 `note`。
- 权重在本次分析的原始值上计算：每道最近仍错误的题 +0.08（最多 +0.30）；完成率低于 50% 时高权重内容 +0.03；临近 3 天且无错题的低权重内容 −0.08。范围 0.05～1.0；反复确认同一反馈不会累加权重。
- 按需求为低分知识点追加每项 30 分钟的专项练习；同一批反馈不重复追加，已有未完成同名练习不重复创建。保留已有未完成工作量、手动任务及已完成记录；使用全科共享预算与考试截止日统一排程，第一段保留原任务 ID。
- 预览不写数据库，列出全科实际安排及容量冲突；有冲突不能应用。任务、预算、考试、分析或自测数据变化后，旧确认返回 409；过期考试、未先预览、容量不足也返回 409。
- 确认时统一提交权重、分析计划、练习任务及全科任务安排；任一写入失败全部回滚。自测题目快照与已交卷结果保持不变。

`quiz` 的 `answer`、`analysis`、`accepted_answers` 在公开分析响应中为空；参考答案保存在服务端，提交自测后才随判分结果返回。生成阶段校验客观题类型及参考答案，失败自动重试一次。
**副作用**：容量校验通过后，`review_plan` 生成该科目每日任务并统筹全科未完成 AI 任务；替换本科旧的未完成 AI 任务，保留已完成记录。

**全科时间口径（2026-10-17）**：画像仍按科目保存目标与基础，每日可用时间由 `/api/study/settings` 统一设置，表示所有科目合计。生成分析前，系统参考全部未结束考试估算本科时间份额；生成后对所有未完成 AI 任务统一校验容量并排程。手动任务和已完成记录保留，同名已完成任务的预计分钟数会从新计划中扣除。`review_plan` 是本科内容建议，跨科统筹后的实际日期以 `/api/tasks` 为准。

分析响应新增可选 `scheduling: {created, applied, conflicts}`。若 `applied=false`，分析内容仍可查看，但新任务不会写入或覆盖原任务；需调整预算、范围或目标后重新生成。不能只看分析请求返回 200 就提示“任务已生成”。

### 查询最新分析
`GET /api/ai/analyses/{exam_id}` — 无历史分析时返回 404。

### 知识点掌握状态（用例 4.9）

`GET /api/ai/analyses/{exam_id}/mastery`：按该用户该科目最近一次覆盖各知识点的已交卷自测计算；未提交和损坏记录不计，空答计错，同次重复题去重。正确率≥80% 为 `mastered`，已测低于80% 为 `weak`，无记录为 `untested`。返回 `exam_id`、`note` 和 `points`，每项含 `name/status/total/correct/score/attempt_id/last_submitted_at/evidence`；证据仅含题目、是否答对/未答，不含参考答案。无分析或访问他人科目返回404。页面交卷后自动刷新，支持手动更新及逐项查看依据。

### 推荐原文依据（4.13）

`POST /api/ai/analyses/{exam_id}/evidence`，body 为 `{"analysis_id":1,"kind":"knowledge","item_index":0}`。kind 支持 knowledge/focus/question_type；索引指向该分析对应列表的原始顺序。固定 analysis_id，避免另一页面重新生成后串到新分析；接口只读，不调用模型、不写库。

返回 `analysis_id/exam_id/item_title/items/note`。每个片段含 `material_id/material_title/source_type/file_type/status/location/page/start/end/content_hash/material_created_at/context/highlight_start/highlight_end/match/note`。status 为 available/changed/unavailable；只有 available 展示高亮原文和资料库入口。PDF 页码、Word 段落/表格行、TXT 行号来自解析器，旧资料只标解析文本偏移，不猜页码。资料正文变更、删除、移出科目或 ID 复用后返回失效状态，不沿用旧片段冒充当前原文。

新分析的知识点、考点和题型可携带 `citations:[{"material_id":1,"quote":"连续原文"}]`；服务端只接受当前用户当前科目中实际存在的引文，重建偏移、创建时间和正文摘要，不信任模型提供的位置。缺少有效引文时仅做明确标注的关键词匹配；无匹配返回空 items 与资料不足提示，不编造来源。

`GET /api/materials/{id}/excerpt?start=...&end=...&content_hash=...&material_created_at=...`：资料库按已校验位置显示上下文，支持超过原详情前 1000 字的片段。创建时间和摘要失效返回409，非法位置416，他人资料404。正文通过纯文本组件呈现，不执行嵌入的 HTML。模型引用核对与关键词定位仅帮助学生检查推荐，不能单凭片段认定必考或出现次数。

## 五·补、资料问答 `/api/ai/qa`（用例 4.5）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ai/qa/conversations?exam_id=1` | 会话列表（按最近更新，最多 20 条，不含消息正文） |
| POST | `/api/ai/qa/conversations` | 新建会话 `{"exam_id": 1, "title": ""}`，title 缺省为「科目名 资料问答」 |

提问行为：
- 只把当前科目**解析成功**的资料正文拼进上下文（问答上限 12000 字），并要求大模型只依据资料回答；
- 带上最近 10 条消息（约 5 轮）作为多轮上下文，支持追问；
- 回答与问题都写入 `qa_messages`，刷新页面后通过会话列表/详情继续；
- 大模型调用失败时回滚本轮提问并返回 `502`；该科目没有可用资料时返回 `400`。
- `LLM_MOCK=true` 时使用本地关键词匹配回答，便于无 Key 演示。

## 六、任务 `/api/tasks`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tasks/today` | 今日待办（未完成在前，按优先级排序） |
| GET | `/api/tasks?date=2026-09-08&exam_id=1` | 按日期/科目查询（参数可选） |
| POST | `/api/tasks` | 手动添加任务 `{"exam_id":1, "title":"...", "plan_date":"2026-09-08", "estimated_minutes":60, "priority":2}` |
| PUT | `/api/tasks/{id}` | **编辑任务（2.6）**：`{"title":"...","plan_date":"...","estimated_minutes":60,"priority":1,"exam_id":2}` 全部可选，仅更新传入字段；`exam_id` 换科目时校验归属 |
| POST | `/api/tasks/check-conflict` | **任务冲突检测（2.8）**：保存前预检，见下 |
| POST | `/api/tasks/{id}/checkin` | 打卡完成 |
| DELETE | `/api/tasks/{id}/checkin` | 取消打卡 |
| DELETE | `/api/tasks/{id}` | 删除任务 |

**冲突检测（2.8）**：`POST /api/tasks/check-conflict`
```json
{"plan_date": "2026-09-08", "estimated_minutes": 120, "exclude_task_id": null, "daily_limit_minutes": 480}
```
- `exclude_task_id`：编辑场景传自身任务 id，避免把自己算进「当天已有」；`daily_limit_minutes` 可选，默认 480
- 响应：`{"conflict": true, "date": "2026-09-08", "existing_minutes": 420, "planned_minutes": 540, "limit_minutes": 480}`
- 口径：当天全部任务（含已完成）预计时长 + 新增时长 > 上限 → `conflict=true`，前端弹提醒但不阻止保存；添加/编辑任务与日历拖拽改期（2.9）保存前均调用本接口

## 八、番茄钟 `/api/focus`（FMZH-SRS-2.10.0）

番茄钟记录是**学习时长统计的唯一依据**；时长按 `exam_id` 归入对应科目，`exam_id` 为空表示未指定科目的自由专注。

未单独设置当日目标时，目标默认继承全科每日预算。任务预计分钟数只用于排程，不作为实际专注时长。

### 记录一次番茄钟
`POST /api/focus/sessions`
```json
{"exam_id": 1, "duration_minutes": 25, "start_time": "2026-10-14T09:00:00", "end_time": "2026-10-14T09:25:00"}
```
- `exam_id` 可选（1~180 分钟内时长）；`start_time` / `end_time` 可不传，缺省按 `end_time=服务器当前时间`、`start_time=end_time-duration` 推算
- 响应 `200`：`{"id": 12, "exam_id": 1, "subject": "高等数学", "duration_minutes": 25, "start_time": "...", "end_time": "...", "created_at": "..."}`
- 科目不属于当前用户时返回 404
- **调用时机**：前端在「暂停 / 重置（已消耗 ≥1 分钟）/ 倒计时结束」时，把自上次落盘以来已专注的**整分钟**写入一条记录；不足 1 分钟不计，同一段时长不重复计。

### 今日汇总与目标达成
`GET /api/focus/today`
```json
{"date": "2026-10-14", "total_minutes": 75, "goal_minutes": 120, "achieved": false,
 "session_count": 3, "by_exam": [{"exam_id": 1, "subject": "高等数学", "minutes": 50}]}
```
`goal_minutes` 为 0 表示当日未设定目标；`achieved` 仅在设了目标且 `total_minutes ≥ goal_minutes` 时为 `true`。

### 设定当日学习时长目标
`PUT /api/focus/goal`，body `{"target_minutes": 120}`（0~1440；`goal_date` 可选，默认今天）
```json
{"goal_date": "2026-10-14", "target_minutes": 120}
```

### 记录查询
`GET /api/focus/sessions?day=2026-10-14&exam_id=1`（参数均可选，按开始时间倒序）

## 十三、站内提醒与通知（`/api/notifications`，模块 6）

所有接口需要登录，数据限定当前用户。没有定时轮询、邮件或浏览器推送；页面打开/刷新时前端显式调用 `POST /check`，普通历史 GET 不生成通知。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / PUT | `/preferences` | `{enabled,exam_enabled,task_enabled}`，全量保存总开关及分类开关；默认均 true，逐项提醒默认关闭 |
| GET / PUT | `/reminders/{kind}/{target_id}` | kind=exam/task；PUT `{enabled,event_time:"09:00",advance_minutes:0~43200}`；当前事项日期 + 基准时刻 - 提前量计算实际提醒时间 |
| POST | `/check` | 检查到期，返回 `{created}`；同事项同到期时刻幂等，已完成任务、已删除事项、已过日期的考试不生成新提醒 |
| GET | `?page=1&page_size=20&unread_only=false` | `{items,unread_count,total,page,page_size}`；page_size 最大 50，未读数不受筛选影响 |
| PATCH | `/{id}` | `{is_read:true/false}`；标记已读或未读 |
| POST | `/read-all` | 全部可见通知标为已读 |
| DELETE | `/{id}` | 从历史移除，保留内部去重凭据，刷新不会重新出现 |

提醒设置响应包括 title、event_date、enabled、event_time、advance_minutes、due_at、timezone。基准时刻使用北京时间 UTC+8（Asia/Shanghai），不修改考试/任务的原安排；事项改期后按新日期计算。当前考试/任务模型只有日期，前端要求用户在设置提醒时确认基准时刻。提前量 0 表示该时刻提醒。

通知项包括 id、target_type、target_id、title（≤50 字）、content（≤200 字）、due_at、created_at、is_read、target_available。时间以带 UTC 偏移的 ISO 8601 返回；due_at 是配置的提醒时间，created_at 是用户打开页面后实际生成时间。旧通知保留当时内容；来源消失时 target_available=false，不能跳往无效事项。

开关暂停生成新通知，已有历史不消失；重新开启后，在下次检查时生成仍有效的到期提醒。修改时间会产生不同的到期事件，历史保留。来源身份除 ID 外核对 created_at，防止事项删除后 ID 重用继承旧提醒或旧跳转。

新增 `reminders`、`notifications`、`notification_preferences` 三表，启动时自动创建；无需修改已有表的列、删除数据库或重新导入数据。账号注销同时清理这三张表。其他历史认证/注销缺陷不属于本模块修复范围。


## 十四、自测与自动判分 `/api/quizzes`（4.6 / 3.5）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/quizzes` | body `{"analysis_id": 1}`，从自己的已成功分析创建一次自测；返回 201 |
| GET | `/api/quizzes?analysis_id=1` | 最近 20 次记录，含 id、status、created_at、score |
| GET | `/api/quizzes/{id}` | 读取自己的答卷；已提交时包含持久化结果 |
| POST | `/api/quizzes/{id}/submit` | body `{"answers": ["B", ["A", "C"], "true", "4"]}`，顺序与题目一致 |

创建/详情返回 `id`、`analysis_id`、`exam_id`、`subject`、`status`、`questions`、`result` 等。未提交时 `result=null`，题目仅含 index、kind、question、knowledge_point、options；选项为 `{"value":"A","label":"选项内容"}`，不返回参考答案或解析。

支持 single 单选、multiple 多选、boolean 判断、fill 填空。每题等分；多选须选全且无错选。判断提交 `true/false`；填空按 NFKC 全半角及空白规范化后精确匹配，区分大小写，支持生成时明确列出的 `accepted_answers`，不做主观或模糊判分。空字符串/空数组表示未作答，按答错收入错题本。题目与参考答案在开始时保存快照，之后重新生成分析不影响当前答卷。

提交后 `result` 包括 score（百分制）、total、correct、wrong、unanswered、mistakes_added、items（逐题参考答案、当时作答、正误、解析、知识点及 collection_id）。后端判分与错题入本在同一事务内完成，失败全部回滚。相同答案重试返回原结果，不重复记分/入本；已提交后更改答案返回 409，须新开一轮。无效作答返回 422；跨用户读取、提交或引用分析均返回 404。

错题存入原 `collections`：以用户及规范化题干去重，批内、跨次与并发提交均不重复；`content` 保存选项、作答、参考答案、解析、知识点及科目，资料页“收藏 · 错题本”可回看。该结果只作为后续 4.9/4.12 的数据基础，本次不包含掌握状态计算与自适应调整。

启动时非破坏性补建 `quiz_attempts`、问答会话与消息表，为旧 users 增加 auth_key、user_profiles 增加 target_band、materials 增加 weight 并按来源回填、旧 collections 增加 question_key 及唯一索引；保留历史重复条目的原文。无需删除数据库，旧登录需重新登录。真实模式结果写数据库；Pages 演示仅在当前会话共享，刷新恢复。
