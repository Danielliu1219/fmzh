## 1. 项目简介

「期末周别慌！」是面向大学生期末复习场景的一站式智能备考网站。学生上传历年题、老师划的重点、课堂笔记、作业练习等多源复习资料，用一句话描述自己的备考目标与学习状态，系统调用大模型分析常考必考内容、计算知识点权重，为不同目标和基础的学生生成**差异化**的复习方案、按天计划与自测题；配套任务打卡、统计图表、压力指数、救急模式等功能，帮助学生在期末周科学高效地复习。

### 项目亮点（需求分析定稿的创新点）

1. **两级权重体系** —— 把「资料权重」（按来源类型衡量资料可信度）与「知识点权重」（按历年题必考点衡量知识点重要性）分离，分析结果既有依据又有个性；
2. **画像驱动的差异化方案** —— 用自然语言描述学习情况，配合川大绩点对应的目标分数区间与学习表单建立画像；基础薄弱者优先核心内容，目标较高者增加综合应用，不同用户得到不同复习策略；
3. **历年题驱动的考点分析** —— 大模型重点提取历年题中的必考题与常考题型，复习重点与自测题贴合真实考试；
4. **人文关怀功能** —— 期末压力指数、临时救急模式、今日最重要的三件事、情绪记录，缓解考前焦虑。

### 核心设计思路

1. **分析对象就是用户上传的资料** —— 历年题、老师划的重点、PPT、课堂笔记、作业、练习题，系统不去网上搜资料。这样更贴近期末复习的真实场景，也避免大模型随意发挥；
2. **用结构化输入管住大模型** —— 「用户输入结构化 + 固定提示词 + 限制输出格式」三件套，让分析结果稳定、可复现；
3. **自然语言先转成固定 JSON**，作为后续分析的依据：

```json
{
  "target": "pass",
  "learning_status": "weak",
  "available_days": 5,
  "daily_hours": 3,
  "weak_chapters": ["极限", "积分"],
  "materials": ["历年题", "老师重点", "PPT"],
  "output_need": ["知识点权重", "复习计划", "自测题"]
}
```

4. **大模型输出也是固定格式** —— 知识点列表、权重分析、常考必考判断、推荐依据、个性化计划、自测题，每一项都有约定好的结构。

## 3. 核心业务逻辑（动手实现前必读）

这些公式和规则是需求分析里定死的，实现时照抄，不要自己改口径。

### 3.1 两级权重体系

- **资料权重**（衡量「资料可不可信」，默认层级，学生可对单份资料手动调整）：
  `老师标注重点 ＞ 历年试题/练习题 ＞ 平时作业/课堂笔记 ＞ 教材章节/PPT/实验报告`
  默认值（0~1）：老师重点 1.00；历年题/练习题 0.85；平时作业/课堂笔记 0.70；教材章节/实验报告 0.55；其他 0.50。学生可在资料编辑弹窗中调整或恢复默认。
- **知识点权重**（衡量「知识点重不重要」，用于复习计划排序与个性化推荐）：
  历年题必考点分析确定**基础值** → 再按**用户画像**（目标/薄弱章节）调整。

### 3.2 用户画像（结构化 JSON）

自然语言描述 + 学习表单，大模型提取为固定 JSON 字段：**备考目标、学习基础、剩余天数、每日可用时长、薄弱章节**。目标通过区间滑条选择，按[川大教务处本科成绩对照表](https://jwc.scu.edu.cn/info/1066/3444.htm)从及格档（绩点 1.0）到 90–100 分（绩点 4.0），共 10 档；`target_band` 保存明确区间并传入分析，旧 `target` 兼容内部三类策略。未选课程也展示公共输入界面；选课后补充本科信息，已有方案可返回修改画像。画像缺字段时前端引导补全。

### 3.3 期末压力指数（0~100）

```
压力指数 = 30×考试密集度 + 30×任务积压率 + 20×(1−任务完成率) + 20×考试临近度
```

- 考试密集度 = min(1, 未来 7 天考试场次÷4)；任务积压率 = 逾期未完成任务数÷总任务数；任务完成率 = 已完成任务数÷总任务数；考试临近度 = min(1, 21÷最近一场考试剩余天数)
- 分档：<40 轻松、40~60 适中、60~80 偏压、≥80 高压；**≥60 首页提示并建议开启救急模式**
- **边界约定**：无考试时考试密集度与考试临近度取 0；考试当天（剩余 0 天）临近度取 1；无任务时任务积压率与任务完成率取 0
- 后端运行期间按北京时间每天00:05后自动保存当日快照（每分钟检查），无需打开页面；启动补当天缺失记录。每个账号每天一条，失败下次重试，不覆盖已有记录。停机或开始使用前的历史日期如实留空，不用当前数据补造历史分数。
- 首页继续使用当前实时压力，另展示当日自动记录与近7日历史；每日记录固定保存计算当时的分数、分项和时间，所以可能与实时值不同。`GET /api/features/pressure` 与 `/api/features/pressure/history?days=7` 只读，不触发保存；静态演示明确使用示例记录。

### 3.4 情绪综合评分（0~5）

```
情绪综合评分 = 0.4×情绪项 + 0.3×完成项 + 0.2×压力项 + 0.1×达标项
```

各分项均已归一化到 0~5，总评分范围精确为 0~5：

- 情绪项 = 5×(情绪自评−1)÷4（情绪自评 1~5）
- 完成项 = 5×当日任务完成率
- 压力项 = 5−压力指数÷20
- 达标项 = 5×连续达标因子；**连续达标因子 = min(连续达标天数,7)÷7**，连续达标天数 = 连续「当日任务全部完成」的天数
- **低分处理（低于 2.5）**：系统在建议之外提供「减轻当日任务 / 暂停半天」选项；学生选择后，在考试日期、每日可用时间、任务优先级约束下重排未完成任务，剩余时间不足时明确提示取舍、不自动增加后续负担；所有调整经学生确认后生效（用例 7.7）

### 3.5 复习计划生成闭环

```
上传资料 → 解析文本 → 资料权重（来源层级）
        → 知识点权重（必考点 × 画像调整）
        → 分级推荐策略（分数区间目标）
        → 按天复习计划 → 自动落为每日任务
        → 打卡/自测 → 进度与掌握状态 → 预览并确认动态调整计划与权重
```

### 3.6 大模型调用约定

- 后端 `LLM_MOCK=true`（默认）：不调用 API，返回内置示例数据，**不需要任何 Key**，可完整走通全流程；
- `LLM_MOCK=false`：调用真实大模型（OpenAI 兼容接口），接口地址、模型名与 API Key 均在 `backend/.env` 配置（见 `.env.example`）；
- 所有大模型输出必须是**固定 JSON 结构**（prompts 在 `backend/app/services/prompts.py`），解析失败要有兜底。

首次自动建立Python虚拟环境、安装锁定依赖并构建完整应用；之后每次检查依赖并重新构建。打开 **<http://127.0.0.1:8000>**，首次注册自己的账号；页面和`/api`由同一进程提供，刷新课程/资料/分析页仍可访问。默认`LLM_MOCK=true`只替换模型响应，其他数据真实保存；大模型API配置保留待填。

- `start.ps1 -PrepareOnly`只准备依赖、构建和检查，不创建数据库或会话密钥；`start.ps1 -Check`只读检查已有环境。
- 不覆盖已有`.env`、`.env.local`、数据库或上传文件，不自动运行`seed_demo.py`；没有本地环境文件也可使用默认配置启动。
- Ctrl+C停止后数据保留。未自定义SECRET_KEY时，首次自动生成数据库同级`.runtime/session.key`并在重启时复用；已有自定义密钥保持原样。备份时保留数据库、uploads、`.runtime`及私有配置。
- 已准备好后可直接执行`backend/.venv/Scripts/python.exe -X utf8 backend/run.py`。需要独立Vite开发时，后端改用`run.py --api-only --dev`。

`npm run build`保留Pages的`/fmzh/`静态演示；`npm run build:app`输出`frontend/dist-app`，固定使用根路径和同源真实`/api`，不受旧前端预览配置影响。完整应用启动检查会拒绝误用Pages产物。

首次安装需要网络及Python/Node.js/npm。完整操作、备份和部署边界见[运行交付](docs/运行交付.md)；本轮在不含原环境/数据/依赖的Windows副本上重新安装并验收。

### 6.3 两个 Mock 开关的区别（容易混，务必分清）

| 开关 | 位置 | 作用 |
|---|---|---|
| `VITE_USE_MOCK` | `frontend/.env.local`（示例见 `.env.example`） | **前端**使用内置演示数据还是调接口；默认 true，设为 false 并重启 Vite 后接真实后端 |
| `LLM_MOCK` | `backend/.env` | **后端**大模型调用返回内置示例还是调真实大模型 API；两者都不需要改代码 |

**接入真实大模型**：到所用大模型平台申请 API Key → 编辑 `backend/.env`：`LLM_MOCK=false` + 填入 Key（`DEEPSEEK_API_KEY=sk-你的key`）→ 重启后端。

## 11. 常见问题

**Q：npm install 很慢 / 失败？**
换国内镜像：`npm config set registry https://registry.npmmirror.com` 后重装。

**Q：5173 端口被占用？**
Vite 会自动换端口（终端会打印实际地址）；或先关掉占用进程。

**Q：登录报错/首页加载失败？**
后端没启动，或 `VITE_USE_MOCK=false` 但没联调。按 6.2 启动后端，或将 `frontend/.env.local` 的 `VITE_USE_MOCK` 设为 true 并重启，用免登录预览。

**Q：AI 分析提示网络错误？**
检查后端 `.env`：`LLM_MOCK=false` 时必须配了有效的 `DEEPSEEK_API_KEY`，否则改回 `true` 用 Mock。

**Q：想重置演示数据？**
重跑 `backend/seed_demo.py` 即可。
